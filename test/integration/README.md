# test/integration

## Назначение каталога
- Интеграционные проверки репозитория событий на реальной базе Postgres, поднятой через testcontainers.
- Валидируют CRUD, поиск ближайших событий и работу миграций.

## Правила зависимостей
- Использует миграции из `../../migrations` и утилиты из `test/util` для подготовки окружения.
- Тесты не должны зависеть от HTTP или фоновых джобов; проверяют только слой хранения/сервиса.

## Конвенции и практики
- Каждый suite поднимает контейнер Postgres, применяет миграции goose и закрывает ресурсы в `TearDownSuite`.
- UUID и временные значения генерируются внутри тестов; длительности уведомлений могут быть заданы строкой.
- Assertions через testify/suite для читаемости.

## Ключевые артефакты
- `events_service_and_repository_test.go` — набор сценариев CRUD, update, delete, поиск ближайших событий.

## Нарушения/риски
- Тесты не покрывают сервисный слой отдельно от репозитория и не проверяют отметку уведомлений/очистку старых событий.
- Использование `NotifyBefore` как строки может не совпасть с типом `INTERVAL` БД, что сделает тесты нестабильными на другом образе Postgres.
