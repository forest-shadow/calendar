# migrations

## Назначение каталога
- Хранит SQL-миграции goose для схемы календаря (Layered-инфраструктура).
- Фокус на таблице `events` и тестовых данных для локального окружения.

## Правила зависимостей
- Используется утилитами миграций (`goose` из `tools/bin`, Dockerfile миграций, Makefile); не импортируется из кода напрямую.
- Версии миграций должны быть применимы как локально, так и в контейнерах (`docker-compose` → сервис `apply-migration`).

## Конвенции и практики
- Формат goose (`-- +goose Up/Down`), дата-штамп в имени файла.
- Схема должна соответствовать доменной модели `internal/events/event.go`; изменения схемы требуют синхронизации DTO/репозитория.
- Тестовые данные разрешены для локального окружения, но не для production миграций.

## Ключевые артефакты
- `20241016191005_create_events.sql` — создание таблицы `events`, сиды для примеров.

## Нарушения/риски
- Миграция использует `gen_random_uuid()` без создания расширения `pgcrypto`; на чистой БД применение упадёт.
- Колонка `notify_before` — `INTERVAL`, в API используется строка ISO 8601 без конверсии, возможен рассинхрон форматов.
- Тестовые данные создаются в основной таблице, не отделены от боевых схем; при переносе в прод потребуется очистка.
