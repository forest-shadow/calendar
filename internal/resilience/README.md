# internal/resilience

## Назначение каталога
- Зарезервировано под устойчивость и отказоустойчивость (ретраи, таймауты, circuit breaker).
- Пока не содержит реализации.

## Правила зависимостей
- Будущие компоненты должны быть инфраструктурными и не знать о домене; подключаться через обертки/мидлвары.
- Не добавлять здесь бизнес-логику или прямые обращения к репозиториям.

## Конвенции и практики
- Предполагается использовать как общий слой для повторов/ограничения запросов внешних адаптеров и фоновых задач.
- При реализации следует предусмотреть конфигурирование через `internal/config` и независимость от конкретных транспортов.
