# internal/transport

## Назначение каталога
- Транспорты приложения; сейчас реализован только HTTP сервер.
- Должен содержать адаптеры для входящих/исходящих соединений (HTTP/gRPC/etc.), изолированные от бизнес-логики.

## Правила зависимостей
- Разрешено зависеть от конфигурации, логгера и конкретного роутера/handler; бизнес-логику не тянем сюда.
- Новые транспорты должны принимать готовые обработчики/роутеры, не создавая сервисы внутри.

## Конвенции и практики
- Выделять сервер как обертку над стандартной библиотекой с явным управлением listener и shutdown.
- Запуск сервера не должен блокировать сборку приложения; ошибки старта должны возвращаться вверх.
- Таймауты, лимиты и middlewares задаются на уровне конкретного транспорта (см. `http`).

## Ключевые артефакты
- `http` — реализация HTTP-сервера.

## Нарушения/риски
- Каталог ориентирован на расширяемость, но пока содержит только HTTP; при добавлении других транспортов нет общих контрактов/портов.
