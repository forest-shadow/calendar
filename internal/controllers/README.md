# internal/controllers

## Назначение каталога
- Входные адаптеры: обработка HTTP-запросов, маршаллинг/анмаршаллинг, валидация и делегирование сервисам домена.
- Сейчас представлен только HTTP-стек в подпапке `http`.

## Правила зависимостей
- Контроллеры зависят от сервисных интерфейсов (`eventService`), `logger` и `apperrs`; прямые обращения к БД, конфигу или джобам запрещены.
- DTO и маппинг должны оставаться локальными; доменные типы можно использовать только как результат вызовов сервисов.

## Конвенции и практики
- Контроллеры должны оставаться тонкими: проверка входных данных, вызов use-case/сервиса, перевод ошибок в HTTP-коды.
- CQRS не выделен: команды и запросы идут через один интерфейс сервиса; при росте функционала стоит разделить.
- Валидация `notify_before` вынесена в контроллер; для остальных полей проверка отсутствует и должна добавляться до передачи в сервис.
- Логирование маршрута происходит через `chi.RouteContext` в `handleError`.

## Ключевые артефакты
- `http` — конкретные обработчики, роутинг и тесты для REST API.

## Нарушения/риски
- Контракт сервиса событий определен локально и дублируется в других пакетах, что усложняет эволюцию API и моки.
- Часть валидации и проверок инвариантов отсутствует: контроллеры принимают сырой ввод и передают его в сервис без проверки границ/обязательных полей.
