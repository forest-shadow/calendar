# internal/controllers/http

## Назначение каталога
- HTTP-ручки на chi для CRUD по событиям и healthcheck.
- Локальные DTO и простая валидация входа (`notify_before` в ISO 8601), маппинг ошибок `apperrs` в статусы.

## Правила зависимостей
- Использовать только интерфейс `eventService`, `logger` и `apperrs`; прямой доступ к БД/репозиторию запрещен.
- Новые маршруты должны объявляться через `router.go` и вызывать сервисы/use-case, не содержать бизнес-логики.
- DTO остаются локальными; доменные типы (`events.Event`) применяются только как вход/выход сервисов.

## Конвенции и практики
- Тело запросов сериализуется/десериализуется через `encoding/json`; после чтения тело закрывается.
- Ошибки отправляются текстом, статус определяется по `errors.Is` с `apperrs`.
- CQRS не разделён: читающие и пишущие операции идут через один сервис; при расширении списка/поиска стоит разделить контракты.
- Предполагается тонкий контроллер: вся сложная логика (валидация периодов, пересечения событий) должна быть в сервисе.

## Ключевые артефакты
- `router.go` — регистрация маршрутов и middleware.
- `events.go` — CRUD-обработчики событий, DTO и маппинг на домен.
- `utils.go` — общая обработка ошибок и парсер ISO 8601 длительностей.
- `healthcheck.go` — простая проверка состояния.
- `events_test.go` — юнит-тесты createEvent с моками сервиса.

## Нарушения/риски
- Маршрут удаления зарегистрирован как `/api/v1/events` без `{id}`, поэтому `deleteEvent` не получает `id` и недоступен для клиента.
- Список событий читается из тела GET-запроса, что не поддерживается большинством клиентов/прокси; фильтры `from`/`to` могут не работать.
- Нет проверки границ дат и обязательных полей; обновление принимает произвольную Map и может записать неожиданные поля в БД через сервис/репозиторий.
- Валидация `notify_before` ориентирована на ISO 8601 строки, тогда как БД хранит `INTERVAL`, форматы могут не совпасть.
- Ответы записываются в тело до `WriteHeader` в `getEvent/getEventsList`, из-за чего статус остаётся значением по умолчанию и теряется явная семантика.
