# internal/jobs

## Назначение каталога
- Фоновые задачи сервиса: уведомление о событиях через Kafka и очистка старых записей по тикеру.
- Предоставляет общий интерфейс `Job` и раннер для параллельного запуска задач.

## Правила зависимостей
- Работают через интерфейс `eventService`, не обращаются к репозиторию/БД напрямую.
- Используют конфиг и логгер для интервалов и логирования; новые задачи должны принимать их через конструктор.
- Kafka-зависимость инкапсулирована в `EventProducer`/`EventConsumer` и не должна просачиваться наружу.

## Конвенции и практики
- Интервалы парсятся из строковых значений конфигурации (`time.ParseDuration`).
- Уведомления отправляются в Kafka: продюсер публикует события, консьюмер читает и помечает их уведомленными через сервис.
- Очистка старых событий работает по тикеру и логирует факт удаления.
- Ошибки прокидываются через общий канал `errCh`; успешная работа не должна блокировать основной поток.

## Ключевые артефакты
- `jobs_runner.go` — интерфейс `Job` и запуск нескольких задач с каналом ошибок.
- `event_notifier.go` — тикер, producer/consumer Kafka, отметка уведомленных событий.
- `event_cleaner.go` — периодическое удаление старых событий.
- `event_producer.go`, `event_consumer.go` — обертки над `franz-go` для отправки и потребления сообщений.

## Нарушения/риски
- `RunJobs` блокирует запуск приложения, ожидая первую ошибку; при остановке контекста это воспринимается как ошибка и валит процесс без graceful shutdown.
- Контекст джобов общий с приложением; остановка по сигналу генерирует ошибку в `errCh`, а не корректный выход.
- Нет обратного давления/ограничения на Kafka producer/consumer; ошибки отправки логируются только через канал, повторов нет.
- Очистка использует порог из сервиса (`DeleteOldEvents` сейчас 30 секунд), не совпадает с требованиями по удалению старше года.
