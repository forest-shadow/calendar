# internal/apperrs

## Назначение каталога
- Sentinel-ошибки уровня приложения для маппинга в HTTP-статусы и единообразной обработки.
- Используются контроллерами для выбора кода ответа.

## Правила зависимостей
- Самостоятельный пакет без зависимостей; может импортироваться из домена, контроллеров и фоновых задач.
- Новые ошибки должны быть независимы от конкретных реализаций инфраструктуры.

## Конвенции и практики
- Ошибки описаны как `errors.New(...)`; при расширении стоит держать их минимальными и явными.
- Контроллеры сопоставляют их с кодами 404/400/409/401; для новых ошибок нужен явный маппинг.
- Бизнес-ошибки из сервисов должны оборачиваться через `%w` для корректной проверки `errors.Is`.

## Ключевые артефакты
- `errors.go` — базовый набор `ErrAlreadyExist`, `ErrNotFound`, `ErrConditionViolation`, `ErrUnauthorized`.

## Нарушения/риски
- Нет единой модели ошибок/Result; сервисы возвращают «сырой» `error`, из-за чего сложнее кодировать доменные состояния без текстовых сравнений.
